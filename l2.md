# What is `l2/`?

`l2/` contains a separate working checkout of this same project at
[`l2/app-main/`](l2/app-main/). It is a **linked Git worktree**, rather than
another Python package or another layer of the FontLab API. Its `.git` file
points to the outer repository's `.git/worktrees/app-main` metadata. The two
checkouts share Git history and objects but have separate working files,
indexes and checkout positions.

As inspected on **12 November 2026**, `l2/app-main/` has a detached HEAD at
`a33d6afac11c907d9c4f751080b89329cafa896b`, while the top-level checkout's HEAD
names `main`. The directory name `app-main` does not mean that it tracks the
current `main` branch. These observations describe local checkout metadata;
they do not establish the current remote head or installed FontLab version.

## How it differs from the main content

Here, “main content” means the files directly under this repository root.

| Area | Top-level checkout | `l2/app-main/` |
| --- | --- | --- |
| Layout | `src/`, `Scripts/`, `tests/`, `examples/`, documentation and build tools | A second copy of the same project layout |
| Python package | `src/fontlabapp/` | Its own `src/fontlabapp/`, with the same import name |
| Source state | Contains additional workflows and changes described below | A separate checkout at the pinned commit, with files differing from the top-level tree |
| Progress records | Root README, WORK, PLAN, TODO and CHANGELOG | Separate copies describing that checkout's work and remaining checks |
| Default build/test scope | Root configuration selects root source and tests | Used when commands explicitly target or run inside this checkout |

The current top-level tree includes the Core PythonQt Labs package and demos
for Open Fonts and Master Overview, Master Compatibility Browser, Node Counts
Across Masters, Interpolation Preview, Font Info and Vertical Metrics,
Designspace Source Comparison, Representation and Notification Explorer, and
UFO Roundtrip Inspector. Those demo files are absent from `l2/app-main/Scripts/`.
The nested checkout also lacks their additional test files.

Some files present in both trees have different contents, including AppShell,
TGlyph, TMetrics, the kerning batch writer, plugin coordinate filters and several
studio modules. Their progress documents differ too. Neither tree should be
treated as a byte-identical backup of the other. The root test extra additionally
includes `uharfbuzz`; the nested checkout's test extra does not.

## Which files to use

For work on the main project, use the top-level [`src/fontlabapp/`](src/fontlabapp/),
[`Scripts/`](Scripts/), [`tests/`](tests/) and [`README.md`](README.md).
Use `l2/app-main/` only when intentionally working with that separate checkout.
Both trees provide `fontlabapp`, so the chosen installation and import path
determine which implementation Python loads; they are not complementary modules.

The root [`pyproject.toml`](pyproject.toml) builds its wheel from
`src/fontlabapp`, limits source-distribution contents to an explicit list that
does not include `l2`, and configures pytest to use `tests` with `src` on its
Python path. Normal root package builds and configured pytest discovery
therefore do not use the nested checkout.

The worktree metadata establishes what the directory is, but does not explain
the name “l2” or identify an active owner. Its presence alone does not prove
that it is disposable, fully integrated, released or native-tested. This
comparison inspects local files and configuration; it does not qualify either
checkout's runtime behavior.
